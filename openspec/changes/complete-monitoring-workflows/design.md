## Context

动机见 proposal.md。现有 ORM 无需变更即可完成账户软删除、告警启停和已读。后端路由无 /api 前缀，线上由 nginx 处理，因此开发代理应剥离 /api。现有浏览器保险箱使用固定 session 字符串，不能视为会话安全保护。

## Goals / Non-Goals

Goals：完善已有入口，保护用户隔离和币种语义，建立可离线运行的回归测试。

Non-Goals：本次不改线上服务，不实现支付及付费报告，不搭建 SMTP，不声称验证真实厂商接口。

## Decisions

- 复用现有表，账户软删除时禁用告警规则，读取统一检查所有权与删除状态；规则硬删除先删除事件，避免外键依赖数据库旧建表方式。
- 把速率计算抽取为共享纯函数供趋势与告警调用，避免服务反向依赖路由。只比较同币种余额；不把配额消耗或月账单累加当作余额。
- 保留绝对日均消耗阈值这一已有界面语义，不引入缺乏基准周期定义的环比告警。
- 本地保险箱新增用户作用域、随机盐和用户口令；仅内存保存解锁口令，退出清空。不自动沿用旧固定口令密文，提示重新录入，避免扩大旧安全问题。
- 计算器使用用户输入的同币种价格而不是内置可能过期的定价，不依赖空的 pricing_models 表。
- 日志调整使用 loguru，仅记录厂商、账户和错误类型，不记录 Key、请求对象或异常完整内容。
- 回归实测发现 passlib 与 bcrypt 5 初始化不兼容，改为直接 bcrypt API，保持既有 bcrypt 哈希兼容；注册时校验 72 字节上限，登录非法密码安全失败。

## Risks / Trade-offs

- 旧 Key 密文不能直接使用 → 界面提示重新输入，不删除旧存储以便用户自行处理。
- 未配置真实数据库和厂商凭据 → 使用临时 SQLite 测试路由/事务以及适配器 mock；生产 PostgreSQL 与真实接口仍需验收。
- 保险箱口令丢失不可恢复 → 明确提示重新录入 Key；HTTP 非 localhost 禁用本地 Key 功能并提示 HTTPS。
- 邮件、报告和厂商账单适配器仍有未完成部分 → 在现有交接文档追加审查发现和后续验收事项，不将其隐藏。

## Migration Plan

安装依赖并执行回归测试和前端构建后由维护方部署；无数据库结构迁移。回滚代码即可恢复接口行为，新的浏览器密文保留但旧版不能读取，需重新录入。
