# AI 成本监控工具 · 功能设计文档

> 版本 v0.1 | 2026-10-26 | 状态：待琴萧确认
> 产品定位：接真实账单/用量的动态成本监控工具，静态计算器为引流入口

## 1. 用户与场景

**目标用户**：同时用 2+ 家 AI API/订阅的开发者与重度使用者（首期就是琴萧这类人的画像）
**核心场景**：
- "我这个月到底烧了多少？哪家在偷偷吃钱？"
- "按现在这个烧法，额度还能撑几天？"
- "订阅制 vs API 按量，我该退哪个？"

## 2. 功能清单（MVP）

### F1 账户接入（核心）
- 添加厂商账户：录入 API Key（首期 6 家）
- Key 加密存储（AES-256-GCM，服务端密钥）
- 连通性测试：接入即拉一次余额验证

**⭐ 接入模式（v0.4：Key 永不上服务器）**

核心架构：**Key 保存在用户浏览器本地（IndexedDB + WebCrypto 加密），请求时随请求头携带，服务端只做内存中转、永不落库**。

| 模式 | Key 存储 | 采集方式 |
|------|---------|----------|
| A. 手动模式（默认） | 无 Key，手动/粘贴录入读数 | 手动快照 |
| B. 本地 Key（主推） | 浏览器 IndexedDB，WebCrypto 加密 | 用户打开页面时自动采集 |

技术方案（B 模式）：
1. 前端把 Key 加密存本地（IndexedDB，密钥由用户登录会话派生）
2. 采集时：前端带 `X-Provider-Key` 头请求我们的后端
3. 后端在**内存中**把 Key 转发给厂商接口，拿到响应、写入 snapshot（快照存数据库，Key 不存），请求结束 Key 即丢夭
4. 后端禁止日志打印请求头，代码层面隔离

为什么需要后端中转（不能浏览器直连厂商）：
- 多数厂商 API 不开 CORS（OpenAI/Anthropic/智谱等），浏览器直连会被跨域拦截
- 用户 IP 暴露给厂商无所谓，但直连不可行，所以中转是必选

**代价（诚实告知用户的权衡）：**
- 服务端没有 Key → 无法在用户不在线时定时采集 → 自动采集只在用户打开网站时触发（打开即拉一次，体验上其实够了）
- 想要真正的离线定时采集？未来可加可选的「上传 Key 加密托管」作为 C 模式，但那是高级选项，不是默认

信任建设（首页文案）：
- 「Key 只存在你的浏览器里，服务器见不到、存不了、丢不了」
- 技术说明文档公开加密与中转细节，接受开发者审视

### F2 用量采集
- 定时采集（默认每 6h，可调）：拉余额 + 配额 + 用量数据
- 采集快照全部入库（趋势分析的数据底座）
- 采集失败告警（Key 失效 / 接口变更）

### F3 成本仪表盘（核心卖点）
- 总览卡片：各账户余额、配额消耗百分比、今日/本月消耗
- 消耗趋势图：按天/周/月的余额变化曲线（可对比多账户）
- 烧钱速率：滑动窗口计算日均消耗 → 预测"额度还剩 N 天"
- 模型分布：哪些模型在吃钱（依赖厂商接口粒度，粒度不够则降级为账户级）

### F4 异常告警（付费点）
- 阈值告警：余额 < X 元 / 配额消耗 > Y% 时触发
- 速率告警：日均消耗环比暴涨 > 50% 提醒
- 通道：站内 + 邮件（微信推送二期）
- 免费版限 1 条规则/账户，付费不限

### F5 订阅计算器（引流，免费）
- 输入：使用量画像（日均 token、主要模型）
- 输出：订阅组合建议 + 月成本预估 + "订阅 vs 按量"对比
- 纯静态定价数据 + 规则计算，无登录可用

## 3. 用户与付费分层

| 功能 | 免费 | Pro（买断/按次） |
|------|------|------|
| 账户接入 | 2 个 | 不限 |
| 仪表盘 | 手动刷新 | 自动采集 |
| 告警规则 | 1 条/账户 | 不限 + 邮件推送 |
| 深度月报 | - | 按次购买（¥3-5/次） |
| 计算器 | ✅ | ✅ |

## 4. 账户接入厂商清单（v0.2 更新）

### 一期（MVP，6 家）
| 厂商 | 类型 | 接口 | 接入难度 |
|------|------|------|----------|
| DeepSeek | 余额制 | 官方 `/user/balance` | ⭐ 简单（官方文档） |
| 智谱 zai | 套餐配额制 | 社区逆向端点 | ⭐⭐ 中（无 SLA，适配器隔离） |
| OpenRouter | 充值积分制 | 官方 `GET /api/v1/credits` | ⭐ 最简单（普通 Key 即可） |
| Anthropic | 按量账单 | 官方 Admin API cost/usage report | ⭐⭐ 中（需 Admin Key `sk-ant-admin`） |
| OpenAI | 按量账单 | 官方 Admin API organization usage | ⭐⭐ 中（需 Admin Key 权限） |
| 硅基流动 | 余额制 | 待验证（文档化程度高，预计简单） | ⭐ 待验证 |

### 二期候选
Kimi（月之暗面）、MiniMax、Google Gemini、Groq、阿里百炼

**国外接入注意点**：
1. OpenAI/Anthropic 都要求**专门的 Admin API Key**（普通 sk- key 拉不了账单），引导用户在控制台创建
2. Anthropic cost_report 可按 workspace/model/key 分组，粒度最好
3. OpenRouter 是「一个 Key 调百模」的聚合站，很多国内用户用它访问海外模型——接入它等于间接覆盖一大批海外模型账户

## 5. 边界与暂缓项（原第 4 节）

- ❌ 不做：多厂商覆盖（二期）、团队版、代理抓取网页账单（合规风险，只用官方接口/端点）
- ⚠️ 依赖风险：智谱 coding plan 用量接口为社区逆向端点，可能变更 → 采集层做适配器模式隔离

## 6. 页面结构（原第 5 节）

```
/login /register
/dashboard          总览仪表盘
/accounts           账户管理（添加/编辑/删除）
/accounts/:id       单账户详情（趋势图/模型分布）
/alerts             告警规则管理
/calculator         免费计算器（无需登录）
/report             深度报告（付费）
```
