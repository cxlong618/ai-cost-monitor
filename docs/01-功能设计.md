# AI 成本监控工具 · 功能设计文档

> 版本 v0.1 | 2026-10-26 | 状态：待琴萧确认
> 产品定位：接真实账单/用量的动态成本监控工具，静态计算器为引流入口

## 1. 用户与场景

**目标用户**：同时用 2+ 家 AI API/订阅的开发者与重度使用者（首期就是琴萧这类人的画像）
**核心场景**：
- "我这个月到底烧了多少？哪家在偷偷吃钱？"
- "按现在这个烧法，额度还能撑几天？"
- "订阅制 vs API 按量，我该退哪个？"

## 2. 功能清单（MVP）

### F1 账户接入（核心）
- 添加厂商账户：录入 API Key（首期 6 家）
- Key 加密存储（AES-256-GCM，服务端密钥）
- 连通性测试：接入即拉一次余额验证

**⭐ 接入模式（v0.4：Key 永不上服务器）**

核心架构：**Key 保存在用户浏览器本地（IndexedDB + WebCrypto 加密），请求时随请求头携带，服务端只做内存中转、永不落库**。

| 模式 | Key 存储 | 采集方式 |
|------|---------|----------|
| A. 手动模式（默认） | 无 Key，手动/粘贴录入读数 | 手动快照 |
| B. 本地 Key（主推） | 浏览器 IndexedDB，WebCrypto 加密 | 用户打开页面时自动采集 |

技术方案（B 模式）：
1. 前端把 Key 加密存本地（IndexedDB，密钥由用户登录会话派生）
2. 采集时：前端带 `X-Provider-Key` 头请求我们的后端
3. 后端在**内存中**把 Key 转发给厂商接口，拿到响应、写入 snapshot（快照存数据库，Key 不存），请求结束 Key 即丢夭
4. 后端禁止日志打印请求头，代码层面隔离

为什么需要后端中转（不能浏览器直连厂商）：
- 多数厂商 API 不开 CORS（OpenAI/Anthropic/智谱等），浏览器直连会被跨域拦截
- 用户 IP 暴露给厂商无所谓，但直连不可行，所以中转是必选

**代价（诚实告知用户的权衡）：**
- 服务端没有 Key → 无法在用户不在线时定时采集 → 自动采集只在用户打开网站时触发（打开即拉一次，体验上其实够了）
- 想要真正的离线定时采集？未来可加可选的「上传 Key 加密托管」作为 C 模式，但那是高级选项，不是默认

信任建设（首页文案）：
- 「Key 只存在你的浏览器里，服务器见不到、存不了、丢不了」
- 技术说明文档公开加密与中转细节，接受开发者审视

### F2 用量采集
- 定时采集（默认每 6h，可调）：拉余额 + 配额 + 用量数据
- 采集快照全部入库（趋势分析的数据底座）
- 采集失败告警（Key 失效 / 接口变更）

### F3 成本仪表盘（核心卖点）
- 总览卡片：各账户余额、配额消耗百分比、今日/本月消耗
- 消耗趋势图：按天/周/月的余额变化曲线（可对比多账户）
- 烧钱速率：滑动窗口计算日均消耗 → 预测"额度还剩 N 天"
- 模型分布：哪些模型在吃钱（依赖厂商接口粒度，粒度不够则降级为账户级）

### F4 异常告警（付费点）
- 阈值告警：余额 < X 元 / 配额消耗 > Y% 时触发
- 速率告警：日均消耗环比暴涨 > 50% 提醒
- 通道：站内 + 邮件（微信推送二期）
- 免费版限 1 条规则/账户，付费不限

### F5 订阅计算器（引流，免费）
- 输入：使用量画像（日均 token、主要模型）
- 输出：订阅组合建议 + 月成本预估 + "订阅 vs 按量"对比
- 纯静态定价数据 + 规则计算，无登录可用

### 二期候选

**国外接入注意点**：
1. OpenAI/Anthropic 都要求**专门的 Admin API Key**（普通 sk- key 拉不了账单），引导用户在控制台创建

## 5. 边界与暂缓项（原第 4 节）

## 7. 2026-10-29 代码审查与本轮补全

本节记录当前代码状态；前文为历史设计，出现冲突时以本节和实现为准。

- 账户：支持手动/本地 Key 模式选择、修改别名、软删除；免费版最多 2 个有效账户。删除后阻止采集、手动快照、趋势访问并停用规则。
- Key：浏览器 IndexedDB v2 按用户隔离，AES-GCM、随机盐和用户保险箱口令；口令仅存页面内存，刷新/退出后需解锁。旧版固定口令记录不自动迁移，需重新录入。HTTPS 或 localhost 才能使用。后端会接触采集请求中的明文 Key，但不持久化，不得宣称“服务器见不到”。
- 采集：校验账户模式，保存厂商采集时间并更新账户最后成功时间；失败返回脱敏错误。手动读数拒绝非有限数值和配额越界，美元文本识别为 USD。
- 趋势：支持 7/30/90 天，余额按币种汇总，显示余额、配额、当日成本曲线和本月成本。余额日均消耗为相邻快照正向减少量之和除以观察时间；充值区间无法识别同时发生的消耗，仍可能低估。
- 告警：支持余额、配额和近 30 天绝对日均余额消耗阈值，12h 冷却，规则启停、删除及事件已读。免费版每账户 1 条启用规则，Pro 最多 20 条；与早期“不限”规划不同。邮件通道尚未实现，接口明确拒绝创建邮件规则。
- 计算器：免登录，手动填入同一币种的 token 单价、日用量和订阅月费，输出 30 天费用与价差。没有内置厂商价格、自动套餐组合或订阅额度保证。
- 登录：直接使用 bcrypt 校验，兼容原 bcrypt 哈希；注册密码 UTF-8 长度不能超过 72 字节。
- 本地开发：Vite 将 /api 前缀剥离后转发至 8001，不占用交接环境中的 8000 服务。

### 尚未完成与外部验收边界

1. 正式环境 HTTPS、强 JWT_SECRET、清理测试账号仍由维护方完成；默认开发密钥不得用于正式上线。
2. OpenAI、Anthropic、OpenRouter、SiliconFlow 仍未用真实 Key 验证。审查发现 OpenAI/Anthropic 账单适配器存在请求参数、响应分桶和分页解析风险，可能产生错误零成本，不能当成已可用的真实账单；需对照官方接口及脱敏样例单独修复验收。
3. SMTP 邮件、采集失败事件通知、支付、报告生成及购买权益尚未闭环。本轮未发送邮件、未连接真实厂商、未部署。
4. 当前趋势不是完整账单对账；同一账户混用历史币种应避免，暂无汇率换算。报告、自动套餐推荐及历史原始响应对象存储仍未实现。
5. 尚未完成真实浏览器移动端交互验收及 PostgreSQL 环境验收。离线测试使用启用外键的 SQLite，覆盖接口状态与数据库写入，不替代生产数据库验收。
6. 原有 .env/pydantic-settings 与 logging 配置尚未整体迁移到 YAML/loguru；本轮采集日志已使用 loguru，后续统一配置需独立迁移并兼容部署配置。
