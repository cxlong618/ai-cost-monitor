# AI 成本监控工具 · 数据库设计

> 版本 v0.1 | 2026-10-26 | 适配 PostgreSQL 15+（FastAPI + SQLAlchemy 2.0）

## ER 总览

```
users ─┬─< accounts ─┬─< snapshots        （余额/配额时序）
       │              └─< api_keys_log     （Key 变更审计）
       ├─< alert_rules ──< alert_events
       ├─< purchases                    （付费记录）
       └─ pricing_models（定价库，全局共享）
```

## 表结构

### users

|------|------|------|
| id | BIGSERIAL PK | |
| email | VARCHAR(255) UNIQUE | |
| password_hash | VARCHAR(255) | bcrypt |
| is_pro | SMALLINT | 0=免费 1=Pro，默认 0（不用 VARCHAR） |

### accounts（厂商账户）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL PK | |
| user_id | FK users.id, CASCADE | |
| provider | VARCHAR(30) | zai / deepseek（适配器注册名） |
| mode | SMALLINT | 0=本地Key 1=手动录入，默认 1 |
| name | VARCHAR(100) | 用户自定义别名 |
| api_key_encrypted | BYTEA | ⛔ v0.4 废弃：Key 不再存服务端。mode=0 时 Key 存用户浏览器 IndexedDB，请求时随头携带，服务端仅内存中转 |
| key_fingerprint | VARCHAR(16) | 用于展示 sk-***abc，避免解密 |
| status | SMALLINT | 0=active 1=key_invalid 2=fetch_error 3=deleted（软删） |
| last_fetch_at | TIMESTAMPTZ | 最后成功采集时间 |
| created_at / updated_at | TIMESTAMPTZ | |
| UNIQUE(user_id, provider, key_fingerprint) | | 防重复添加同一 Key |

### snapshots（采集快照，核心时序表）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL PK | |
| account_id | FK accounts.id, CASCADE | |
| fetched_at | TIMESTAMPTZ | 采集时间，索引 (account_id, fetched_at DESC) |
| raw_payload | JSONB | 原始响应（接口变更时回溯重算） |
| balance_total | NUMERIC(12,4) | 总余额（充值型，deepseek） |
| balance_granted | NUMERIC(12,4) | 赠送余额 |
| balance_topped_up | NUMERIC(12,4) | 充值余额 |
| currency | VARCHAR(8) | CNY / USD |
| quota_used_pct | NUMERIC(5,2) | 配额消耗百分比（套餐型，zai） |
| quota_limit | NUMERIC(18,0) | 配额上限（token 数，若接口提供） |
| quota_remaining | NUMERIC(18,0) | 剩余配额 |
| quota_window | VARCHAR(30) | daily / weekly / monthly（配额重置周期） |

> 设计要点：充值型（余额制）与套餐型（配额制）统一在一张表，空字段容忍；`raw_payload` 落原始 JSON，厂商接口改版可重放。

### alert_events（告警事件）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL PK | |

## 索引与运维要点

1. `snapshots(account_id, fetched_at DESC)` — 趋势图主查询路径
2. snapshots 按月分区（数据量增长后），MVP 可先不分区但保留字段规范
3. 快照保留策略：>90 天的降采样为日粒度（定时任务）
4. API Key 安全（v0.4）：Key 永不上服务器——浏览器本地 IndexedDB + WebCrypto 加密存储，请求时随头携带，后端内存中转转发给厂商，响应入库后 Key 即丢弃；日志禁止打印 Key 头

## 与功能映射

- F3 仪表盘 ← snapshots 时序查询 + 滑动窗口计算烧钱速率（应用层）
- F4 告警 ← 每次采集后跑规则引擎 → alert_events
- F5 计算器 ← pricing_models 纯读
